# D5 — Marcação de gerenciados, lockfile e drift

**Onda:** C · **Depende de:** D2 · **Decisão:** 0001 §7.3

## 1. Resultado

Todo model gerenciado carrega os marcadores que outras ferramentas já leem, e o Strata detecta
quando um `.sql` gerenciado foi alterado fora dele.

| Marcador | Onde | Mantido por |
| --- | --- | --- |
| tag `strata:managed` (+ `strata:<projeto>`) | `config.tags` do model | `yamlEdit.managed.ts` |
| `config.meta.strata: { managed: true, generator: "strata", generator_version }` | YAML do model | `yamlEdit.managed.ts` |
| cabeçalho `-- @generated by Strata — edite pelo canvas; edições manuais tornam este model manual.` | 1ª linha do `.sql` | geração da D4 |
| `<caminho do .sql> linguist-generated=true` | `<domínio>/.gitattributes`, entre marcadores `# strata:begin` / `# strata:end` | `managed.ts` |
| `caminho → { sha256, generator_version }` | `<domínio>/.strata/generated.lock.yml` | `managed.ts` |

`generator_version` = versão do `package.json` do Strata.

## 2. Regras

- **Autoridade:** gerenciado ⇔ tag `strata:managed` **e** `meta.strata.managed: true`. Divergência →
  manual, com problema informativo "marcadores divergentes".
- **Drift** (sha do lock ≠ sha do arquivo) ao carregar: o model entra em estado `drift`, a seção
  Transformação fica bloqueada e aparece a escolha:
  - **Tornar manual** → remove tag, `managed`, cabeçalho, entrada do `.gitattributes` e do lock; o
    `.sql` fica como está.
  - **Regenerar** → confirmação explícita mostrando o diff que será perdido; regrava e atualiza lock.
- **Editar o `.sql` gerenciado dentro do Strata** (aba dbt da D3) → mesma escolha antes de gravar.
- **Remover um model gerenciado** remove sua entrada do lock e do `.gitattributes`.
- Os marcadores de `.gitattributes` fora do bloco `strata:begin/end` nunca são tocados.

## 3. Verificação para CI

`scripts/strata-verify.mjs` (`npm run strata:verify`): percorre o domínio, recalcula os hashes,
confere os marcadores e sai com código ≠ 0 listando cada model em drift ou com marcadores
divergentes. Adicionar um passo `strata:verify` ao job `verify` de `.github/workflows/ci.yml`
**somente quando houver domínio dbt no repositório** (o passo detecta e sai 0 se não houver).

## 4. Gates (10)

1. Vitest: gerar model gerenciado → os 5 marcadores presentes e consistentes.
2. Vitest: tag removida à mão → model manual + problema "marcadores divergentes".
3. Vitest: `.sql` alterado sem atualizar o lock → `drift`.
4. Vitest: "Tornar manual" remove os 4 marcadores e preserva o `.sql` byte a byte.
5. Vitest: "Regenerar" sem confirmação → nenhuma escrita (função pura com flag).
6. Vitest: `.gitattributes` com linhas do usuário fora do bloco → intactas após adicionar e remover
   models.
7. `validate.sh`: no `manifest.json` do `dbt parse`, todo gerenciado tem a tag e
   `config.meta.strata.generator == "strata"`; `dbt ls --select tag:strata:managed` lista exatamente
   os gerenciados.
8. `npm run strata:verify`: exit 0 no `kitchen-sink/` limpo; exit 1 com o nome do model após alterar
   um `.sql` gerenciado.
9. Cypress `managed-drift.cy.ts`: alterar o `.sql` em disco pela API de teste → recarregar → aviso de
   drift; "Tornar manual" → seção Transformação some e marcadores removidos em disco.
10. CI: job `verify` executa `strata:verify` e ele sai 0 no repositório atual (evidência: saída local
    do mesmo comando).
